## 実行手順（認証情報のある環境で）

1. Google Cloud Console で「YouTube Analytics API」「YouTube Data API v3」を有効化し、OAuth クライアント（デスクトップ）を作成 → `credentials.json` をリポジトリ直下に置く（.gitignore 済み）
2. チャンネル所有者アカウントで認可（初回のみブラウザが開く。`yt_token.json` に保存され、以後はブラウザ不要。このファイルを別マシンに持ち込めばそこでも実行できる）

```bash
pip install -r requirements.txt   # google-auth-oauthlib / requests
python3 COO/scripts/kins_yt_analytics.py --credentials credentials.json --token yt_token.json
```

- 出力先: `clients/KINS/output/`（`--out-dir` で変更可）。ファイル名の日付は実行日（JST）
- 依頼を絞る: `--only 1,2`　／　END_SCREEN の閾値: `--endscreen-max 5`　／　依頼3の対象本数: `--traffic-top 20`
- Data API の動画一覧が使えない場合: `--videos-csv clients/KINS/output/kins_videos_innertube_20260920.csv`
- 依頼2の特定を手で上書き: `--retention-id "超有料級 / 7年ぶりに / コストコ=VIDEOID"`
- アクセストークン直指定も可: `YT_ACCESS_TOKEN=ya29... python3 COO/scripts/kins_yt_analytics.py`（約1時間で失効）

## 取得仕様のメモ（数値の解釈ではなく、API 仕様上の注意）

- **日付は PT 基準**。Analytics API の startDate/endDate は太平洋時間の日付。公開日は Data API の publishedAt(UTC) を PT に変換して startDate にし、CSV には `publishedAt`(UTC) / `publishedAt_JST` / `startDate_PT` / `endDate_PT` を併記する。JST 深夜公開の動画は PT では前日扱いになる
- **突き合わせ**: `kins_reconcile_*.csv` に Studio の5期間と同じ日付でのチャンネル合計を出す。加えて 3 期間を PT で 1 日前倒しした値も並べるので、JST/PT ずれの当たりがつく
- **impressions / impressionClickThroughRate** は Analytics API v2 の公開 metrics に無い可能性が高い。取れなければ列は空欄のまま、`failedMetrics` 列と `kins_run_*.log` に記録する（依頼1・突き合わせとも）
- **`dimensions=video,insightTrafficSourceType` の同時指定**が API に拒否された場合は、上位N本を `dimensions=video` で取ってから 1 本ずつ `insightTrafficSourceType` を取る（結果は同じ形式）
- **END_SCREEN 一覧** (`kins_traffic_endscreen_*.csv`): insightTrafficSourceType=END_SCREEN は「他動画の終了画面からその動画へ流入した視聴」。行が無い動画は `endScreenViews` 空欄 + 備考「行なし(0)」で載せる
- **依頼4**: cardImpressions/cardClicks/cardClickRate と annotationImpressions/annotationClicks/annotationClickThroughRate をグループ別に取り、拒否された metric は空欄 + ファイル末尾に注記
- ゼロ・欠損は埋めない。行が返らなかった動画は該当列が空欄
- 未達判定: 公開日(PT)+27日+2日（反映遅れ）が実行日(PT)を超える動画は `kins_conv28d_notyet_*.csv` へ
